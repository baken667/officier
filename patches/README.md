# Патчи Officier

Модификации от 2026-09-09 к ONLYOFFICE, разработанному Ascensio System SIA.
Применяются условия [LICENSE](../LICENSE), включая сохранение атрибуции.

## Состав

| Патч | Изменение |
| --- | --- |
| `0001-enable-customization` | Community возвращает `branding`, `customization`, `advancedApi` равными `true` |
| `0002-remove-community-quotas` | `_checkLicenseAuth()` возвращает исходный статус для Community без коммерческой лицензии, без проверки продуктовых квот редактирования, live view и числа пользователей |

Второй патч снимает проверку, а не увеличивает число 20 до другого конечного числа.
Уже существующий `LICENSE_CONNECTIONS_OS = 2147483647` остаётся для совместимости
информационных ответов API. Ошибочный или истёкший статус не превращается в Success.
Условие ограничено `packageType === PACKAGE_TYPE_OS` и `hasLicense === false`.

Квоты продукта не равны пропускной способности: CPU, память, конвертеры и база данных
по-прежнему ограничивают фактическую нагрузку. JWT, доступ к документам, режим view,
права edit/copy/download, проверки URL, паролей и лимиты защиты от перегрузки не меняются.
Multi-tenant режим остаётся выключенным; коммерческие и tenant-лицензии не подменяются.

## Что не реализовано переключением флагов

- Мобильный интерфейс: `web-apps/apps/documenteditor/mobile/src/lib/patch.jsx`
  содержит пустые обработчики toolbar, шрифтов, стилей и таблиц. Включить один
  `isSupportEditFeature()` недостаточно для полноценного редактора.
- `advancedApi: true` открывает существующие проверки в `sdkjs`, но не добавляет
  отсутствующие реализации. В закреплённом `web-apps/apps/api/documents/api.js`
  нет `createConnector`; его появление не обещается.
- Флаги брендинга разрешают существующие настройки интеграции. Сами логотипы,
  юридический экран и оформление Officier ещё требуют реализации.
- React без iframe — отдельная переделка frontend runtime, см.
  [архитектурное решение](../docs/react-without-iframe.md).

## Применение

Требуются Git и Python 3.9+. Для unit-тестов — Node.js 22+.

```sh
bash scripts/bootstrap.sh
python3 scripts/patches.py status
python3 scripts/patches.py check
python3 scripts/patches.py apply
python3 scripts/patches.py revert
```

Повторное применение/отмена не меняют уже обработанные файлы. До изменений
проверяются ревизии всех компонентов, SHA-256 файлов и применимость всех патчей.
При несовпадении локальные правки не затираются. При ошибке применения откатываются
уже выполненные операции текущего вызова. Не редактируйте те же файлы параллельно
с работой скрипта. Manifest описывает непересекающиеся патчи к исходной ревизии.

Нельзя просто смонтировать эти исходники поверх произвольного готового образа:
патчи привязаны к конкретным ревизиям, а запакованные сборки могут содержать
скомпилированный код. Они должны войти в процесс сборки собственного DocumentServer.

## Проверки

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/patches.py apply
node --test tests/capabilities.test.cjs
```

Проверены повторное применение, отмена, отказ при другой ревизии/локальных правках,
предварительная проверка всей серии, откат при неверном результате, флаги Community,
обе ветки квот, сохранение ошибочного статуса и проверки других редакций.
Quota-тест исполняет функцию из реального `DocsCoServer.js` с подставными счётчиками;
полный HTTP/WebSocket-сервер, авторизация и реальное совместное редактирование здесь
не запускаются. Для релиза ещё нужны сборка, открытие/сохранение DOCX, несколько
совместных сессий, проверка режима просмотра и неверного JWT на работающем сервере.
