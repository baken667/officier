# Разработка Officier

## Основа

- Форк: <https://github.com/baken667/officier>.
- Upstream: <https://github.com/ONLYOFFICE/DocumentServer>.
- Исходная ревизия: `f580eb58439432310943ece02c9730c6a21365e7` (`master`).
- Дата подготовки форка: 2026-09-09.
- Рабочее название: Officier; визуальный стиль пока не определён.

Репозиторий сохраняет историю DocumentServer и фиксирует компоненты через Git
submodules. Это исходники, а не готовая запускаемая сборка. Подготовка репозитория
сама по себе не изменяет ограничения установленного ONLYOFFICE или Docker-образа.

## Получение исходников

```sh
git clone git@github.com:baken667/officier.git
cd officier
git remote add upstream https://github.com/ONLYOFFICE/DocumentServer.git
bash scripts/bootstrap.sh
```

По умолчанию загружаются `server`, `web-apps` и `sdkjs` на ревизиях, записанных
в основном репозитории. Для остальных компонентов используйте
`bash scripts/bootstrap.sh --all`. Полный набор исходников значительно больше.
Скрипт не устанавливает зависимости и не запускает сборку.

Адреса в `.gitmodules` сделаны абсолютными: исходные `../server.git` и подобные
в форке разрешались бы относительно аккаунта владельца форка.

## Где менять продукт

| Компонент | Назначение |
| --- | --- |
| `server/Common/sources/license.js` | Параметры Community Edition: подключения, branding, customization |
| `server/Common/sources/constants.js` | Константы лимитов и типов редакций |
| `server/DocService` | Проверки на стороне сервера и совместное редактирование |
| `web-apps/apps` | Интерфейсы редакторов, тексты и ресурсы брендинга |
| `sdkjs` | Клиентский движок редакторов |
| `core` | Конвертация и обработка документов |

Проверка исходников зафиксированной версии показала:

- `LICENSE_CONNECTIONS_OS` уже равен `0x7fffffff` (2 147 483 647).
- `readLicense()` использует его для `connections` и `connectionsView`,
  а `usersCount` возвращает равным нулю.
- `_checkLicenseAuth()` в `DocsCoServer.js` сравнивает число подключений с этими
  значениями. Таким образом, в обычном Community-пути этих исходников порог не 20.
- `LICENSE_CONNECTIONS = 20` также существует, в частности используется
  в логике tenant-лицензий; это не повод глобально заменять все числа 20.
- `branding`, `customization` и `advancedApi` в `readLicense()` остаются `false`.

Это статическая проверка исходников, а не нагрузочный тест или проверка готового
Docker-образа. Никакие runtime-флаги в стартовом коммите форка не изменены.

Далее нужно определить требуемые изменения: мобильное редактирование,
кастомизация или другие возможности. Для подключений — проверить превышение
старого порога на работающей собственной сборке.
Для брендинга — определить название, логотип, цвета, ссылки и экран сведений о продукте.

Изменения внутри подмодулей не сохраняются обычным коммитом основного репозитория.
Перед такими изменениями создайте форк соответствующего компонента, подключите его
как `origin`, сохраните исходный адрес как `upstream`, обновите URL в `.gitmodules`.
Сначала опубликуйте коммит компонента, затем коммит с его новым SHA в Officier.
Иначе другой разработчик не сможет получить нужные исходники.

## Сборка и обновления

Инструкция upstream по сборке доступна из раздела **How to build** в
[исходном README](../Readme.md#how-to-build). Build tools и упаковка находятся
в отдельных репозиториях ONLYOFFICE; готовый контейнер Officier пока не подготовлен.

Для обновления основы:

```sh
git fetch upstream
git switch -c update/upstream
git merge upstream/master
bash scripts/bootstrap.sh
```

Перед публикацией обновления проверьте конфликты `.gitmodules`, лицензии,
изменения в форках компонентов, сборку и работу редакторов.
